# 面试自查

| 问题 | 应能从代码解释的要点 |
| --- | --- |
| 为什么是 Agent？ | 在线适配器接收模型 function calls，LangGraph 条件循环执行观察和下一决策；离线为固定策略，仅验证同一执行器合同 |
| RAG 用了什么？ | 中文二元字符+单字 FTS5/BM25，筛选与可追溯引用；没有 embedding，不能称向量检索 |
| 如何避免幻觉数字？ | 不接收自由数字；finish 只引用已有 aggregate 结果 ID，服务端构建表格 |
| 引用正确就代表结论正确吗？ | 只验证存在性、范围、原文偏移和哈希；语义支持与标注质量仍须人工抽查 |
| 如何防 prompt injection？ | 原文为数据；工具白名单、extra forbid、参数化 SQL、不可更改 dataset、无 shell/任意路径；不宣称对所有注入有理论免疫 |
| 为什么 checkpoint 不直接存聊天摘要？ | 恢复必须知道已完成调用与结果、下一游标、绑定版本；摘要不能保证不重复执行 |
| 恢复能 exactly-once 吗？ | 本地只读工具结果可一致提交；外部模型请求无法跨提供商原子提交，未知结果需人工确认 |
| 怎么控制钱？ | 发送前保守预留、独立记录 provider usage、步骤/时间/输出上限，不把估算当账单 |
| SSE 与轮询如何选择？ | UI 轮询状态；SSE 提供事件游标重放，断线不重跑。单进程工作台，无分布式吞吐承诺 |
| 数据偏差在哪里？ | 定向关键词、平台推荐、重复帖子、表达倾向；分母是本批成功标注反馈，不能解释为全体乘客满意率 |
| 怎样证明比脚本好？ | 同数据/问题/预算做确定性基线、单次LLM、Agent、检索/校验消融；目前仅有合成工程合同，真实对照仍待实施 |
| 最主要的当前限制？ | 无在线效果证明、无正式人工黄金集、检索在内存中构建、仅本机单进程服务 |

建议按 `contracts.py → tools.py → graph.py → journal.py → agent_report.py → test_agent.py` 顺序阅读，并亲手做一次新工具的小改动与测试，不只背术语。
